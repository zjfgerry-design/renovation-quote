# 装修建材智能报价系统 · Renovation Quote

面向中国装修公司、建材商家的中文网页 MVP。使用 Next.js App Router、React、TypeScript、Tailwind CSS，无登录、数据库、AI API 或收费服务。

## 安装与运行

要求 Node.js 20.9+（当前在 Node.js 24.19.0 / npm 11.9.0 验证）。

```sh
npm ci
npm run dev
```

浏览器打开 http://localhost:3000。生产模式本地验证：

```sh
npm run build
npm start
```

## 功能与使用

- 工作台：材料数、当前报价明细数和总额，提供流程入口。
- 材料管理：12 条虚构建材演示数据，支持搜索、添加、编辑和确认删除。
- 创建报价：填写客户、项目、日期，选择材料、输入数量、修改数量或移除明细。
- 预览：填写必要信息后打印 A4 报价单，浏览器选择“另存为 PDF”；建议关闭页眉页脚。
- 页面适配桌面、平板与手机；窄屏材料表支持横向滚动。

材料单价以整数分保存，数量最多三位小数，使用 BigInt 对乘法结果四舍五入到分；总额累加各单项金额。单价上限 1,000,000 元，数量上限 100,000。材料添加到报价时保存快照，后续修改或删除材料不会影响已有明细。数量编辑在离开输入框时校验并保存；非法输入恢复原值。

## 数据与限制

数据使用当前浏览器当前站点的 localStorage（键 `renovation-quote-v1`）保存。刷新可恢复，但不会跨浏览器、设备或域名同步。清理浏览器数据可能导致丢失。首次访问使用演示材料，未修改前无需写入存储。

保存失败时页面明确提示；读取到损坏数据时不覆盖原值，当前会话仍可操作。只有一份当前报价草稿，尚无多报价归档、备份导入导出、税率折扣、账号或云同步。所有演示数据均为虚构，金额仅用于演示。正式业务使用前请自行核对并及时打印保存。

## 检查与测试

```sh
npm run typecheck
npm test
npm run build
npm run test:e2e
```

单元测试覆盖十进制输入、整数金额与舍入、材料快照及损坏数据。浏览器测试覆盖材料增删改、报价编辑、刷新保存、删除材料后快照、预览、生成 A4 PDF、移动宽度与损坏数据保护。

浏览器测试默认使用 `/usr/bin/chromium`，其他环境通过 `CHROMIUM_PATH=/path/to/chromium npm run test:e2e` 指定 Chromium 路径。配置自动启动本地开发服务器；PDF 验证输出位于 `/tmp/renovation-quote-test.pdf`。浏览器测试需要允许启动子进程和监听本地端口。

## 代码结构

- `src/app/`：工作台、材料管理、报价编辑、打印预览与响应式样式。
- `src/components/`：应用导航与本地数据状态管理。
- `src/lib/model.ts`：数据类型、演示数据、金额计算与存储格式校验。
- `tests/`：业务单元测试与浏览器流程测试。

本项目尚未部署生产环境。

## 工程模板与 Excel 预算导入

新增入口：`/templates`（工程报价模板）、`/import`（Excel 预算导入）、`/engineering`（工程报价编辑与打印）。

1. 工程模板可手动添加、修改、删除，保存分类、名称、单位、材料单价、人工单价、工艺及默认数量。每次从模板创建独立工程报价，后续改模板不影响已有报价。
2. Excel 导入接受 `.xlsx`，使用 ExcelJS 在浏览器本地解析，动态加载解析库；无上传接口、AI 服务、宏或公式执行。选择文件后可看封面文本、校对预算明细并预览主材计划。
3. 预算工作表须名为“预算表”，前四行视为标题/表头，第五行起按 A—I 列（序号分类、项目、数量、单位、材料单价、材料合价、人工单价、人工合价、说明）识别。分类支持 `A、` 等标题。空行、合计、小计、总造价和跨项目列合并的备注不参与计价。
4. 只使用公式已有缓存（包括合法零结果），不计算或刷新公式，不访问外部引用。缓存可能过期，必须人工核对；缺少或错误的数量/单价缓存留空并阻止保存。合并的数值列不重复读取为另一种费用；明确标记人工处理。原表 F/H 合价仅供比较，最终按校对后的数量与单价重算。
5. 校对全部字段并勾选确认后，可保存为模板或创建工程报价。修改字段会重置确认。数量允许显式零（例如暂不施工项），支持三位小数；单价支持两位小数。更多精度保留原文本并要求人工决定取值，不静默舍入。材料费和人工费分别用整数分 × 千分数量计算，各项四舍五入至分后再汇总。
6. 工程报价支持修改客户、日期、项目、工程明细，保存后预览和 A4 打印 / PDF。未列明的税率、折扣、管理费规则不会自动套用，请人工转换为明确的数量、单位和单价。

### 真实样表兼容性验证

已在当前环境读取用户附件并测试实际解析：85 行预算中识别 48 个项目、7 个分类，跳过 37 行表头、分类、汇总或备注，识别主材计划 15 条。第 15、16 行数量超过三位小数；第 71、72 行有缺失材料单价、费率单位或跨价格列合并，均要求人工校对。未自动修改这些真实预算值。附件与客户信息不纳入仓库，自动化测试全部使用虚构工作簿。另已在 Chromium 浏览器中对真实附件完成生产构建导入检查：上述识别数量一致，4 项需人工修正，无 POST 上传、无确认前自动保存、无客户端异常。

如需复测其他样表，在导入页面选择文件即可；先在 Excel 中重算并保存有助于更新公式缓存，仍须检查结果。此版不保证兼容任意自定义列布局、`.xls`、加密文件或复杂管理费规则；主材计划仅提供预览，不保存采购任务。

### 容量、备份与旧数据

工程模板与工程报价独立存于 `renovation-engineering-v1`，不改动原 `renovation-quote-v1` 数据。工程保存采用先校验、先持久化、再更新状态；存储失败不跳转、不显示成功，编辑仍保留在当前页面。工程 JSON 限制 3 MB，浏览器总配额还可能更低；请定期点击“导出本地备份”。备份下载包含两个存储键的原始字符串，可能含真实客户资料；请妥善保管。本版暂未提供备份恢复界面。

文件限制：8 MB 压缩文件、ZIP 目录声明解压大小累计 32 MB、最多 20 张表、每表 2000 行/100 列、最多 1000 个工程项目。异常、ZIP64、损坏或不匹配格式会报错。ZIP 大小检查是资源限制措施，不是对所有恶意压缩文件的完整防护；仅使用可信来源的预算文件。

测试新增：分类/汇总排除、合并格、零缓存/缺缓存/错误缓存、超精度与异常数字、损坏工作簿、整数材料人工费用、浏览器真实 `.xlsx` 上传与人工核对、模板转报价、旧报价保留、存储配额失败。所有自动化文件均在测试内生成，无真实数据夹具。
